# Plan 17-02 — `PlantationCard` expandible con sección inline de Parcelas

## Goal

Enriquecer `PlantationCard` con una fila inferior nueva ("Parcelas: N" + chevron rotatable) que, al tocarse, expande inline una sección con la lista de parcelas (reutilizando `ParcelaRow` de 17-01). Es un atajo de navegación: tap en el chevron → expand; tap en una `ParcelaRow` inline → `GruposScreen` scoped; long-press → `ParcelaFormModal` modo editar (D-17-10..14). El estado expandido es local al card (D-17-13), animado con `LayoutAnimation` (D-17-14). Esta doble interacción (body del card → screen completa; chevron → expand inline) es intencional (D-17-11).

### Task 2.3: Wirear estado expandido + handlers de parcela en `PlantacionesScreen`

**Files (modify):** `mobile/src/screens/PlantacionesScreen.tsx`

**What:**
- Agregar estado local: `const [expandedPlantationId, setExpandedPlantationId] = useState<string | null>(null)`. Solo UN card expandido a la vez (Claude's Discretion — más limpio que multi-expansion, también ayuda a performance).
- Por cada item del `FlatList`, calcular `expanded = expandedPlantationId === item.id`. Si está expandido, llamar `useParcelas(item.id)` — **pero `useParcelas` no se puede llamar dinámicamente dentro de `renderItem`**. Solución: crear un componente wrapper interno `<ExpandablePlantationCard plantation={item} expanded={...} onToggle={...} />` que llama `useParcelas` solo cuando `expanded === true` (usa `expanded ? plantacionId : undefined` y el hook devuelve `[]` si undefined, ver Task 2.4).
- Handler `handleToggleExpand(id)`: invoca `LayoutAnimation.configureNext(LayoutAnimation.Presets.easeInEaseOut)` y luego `setExpandedPlantationId(prev => prev === id ? null : id)`.
- Handler `handleParcelaInlinePress(parcelaId)`: navega a `/plantation/${plantacionId}?parcelaId=${parcelaId}` (mismo patrón que `ParcelasScreen`).
- Handler `handleParcelaInlineLongPress(parcela)`: abre `ParcelaFormModal` en modo edit. Esto requiere mover el estado del modal al `PlantacionesScreen` (o usar un modal global). **Decisión:** declarar `const [editingParcela, setEditingParcela] = useState<Parcela | null>(null)` en `PlantacionesScreen`, renderizar `<ParcelaFormModal mode="edit" parcela={editingParcela} visible={!!editingParcela} onClose={() => setEditingParcela(null)} />` al final del JSX.
- Pasar las 4 nuevas props al `<PlantationCard />` invocado en el `FlatList.renderItem`.

## Risks & Mitigations

1. **`stopPropagation` no funciona en todos los nesting de `Pressable` en RN** — riesgo de que tap en chevron también dispare `onPress` del card. Mitigación: usar `Pressable` anidado con `onPress={(e) => { e?.stopPropagation?.(); ... }}` (pattern ya usado en `PlantationCard.tsx` líneas 111, 121, 132 para los iconos del strip). Verificar empíricamente en Task 2.2.
2. **`LayoutAnimation` requiere flag Android** — sin `UIManager.setLayoutAnimationEnabledExperimental(true)` la animación es saltada en Android. Mitigación: agregar el flag al top del archivo `PlantationCard.tsx` (o mejor, en `app/_layout.tsx` para que aplique global) y verificar memory `project_android_only.md` (proyecto Android-only). Si causa side-effects, fallback a `Animated.View` con `height` interpolation.
3. **`useParcelas` llamado en cada card carga todas las parcelas aunque el card esté colapsado** — overhead por card. Mitigación: `useParcelas` ya es reactivo y eficiente (single query `listByPlantacionWithStats`). 10 plantaciones × 1 query simple = aceptable. Si los benchmarks muestran problema, dividir en `useParcelasCount(plantacionId)` (single COUNT) para cards colapsados y `useParcelas` solo cuando `expanded === true`.
4. **Empty state cuando parcela tiene 0 parcelas** — UI confusa si todas las plantaciones aparecen con "Parcelas: 0" + chevron expandable. Mitigación: si `parcelasCount === 0`, el chevron sigue visible pero al expandir muestra el empty state minimal "Sin parcelas — toca + en la lista" + un mini CTA que navega a `ParcelasScreen`.
5. **Modal edit centralizado en `PlantacionesScreen` se desinconta del modal de `ParcelasScreen`** — riesgo de duplicación. Mitigación: ambos screens renderizan su propia instancia del mismo `<ParcelaFormModal>` componente. NO duplicamos lógica (mismo componente). Es el pattern correcto (CLAUDE.md §8).
