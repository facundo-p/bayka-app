# Plan 17-01 — ParcelasScreen + ParcelaRow + ParcelaFormModal + routing

## Goal

Crear la nueva pantalla `ParcelasScreen` y todos los componentes que la sostienen: `ParcelaRow` (fila reutilizable), `ParcelaFormModal` (full-screen modal único para crear y editar, D-17-01), hook `useNewParcela`, y las rutas expo-router `(tecnico|admin)/plantation/parcelas.tsx`. Además, redirige el `onPress` del `PlantationCard` desde `PlantationDetailScreen` hacia esta nueva pantalla (PUI-02). El resultado: el usuario puede entrar a una plantación, ver/crear/editar/borrar parcelas, y navegar a sus grupos.

## Success Criteria

- [ ] (ROADMAP #1) Tap en `PlantationCard` navega a `ParcelasScreen` (no a `PlantationDetailScreen`/grupos como antes).
- [ ] (ROADMAP #1) Tap en una `ParcelaRow` navega a `GruposScreen` scoped (la integración final la cierra Plan 17-03 cuando refactoriza `PlantationDetailScreen`; este plan deja la navegación apuntando a `/plantation/${plantacionId}?parcelaId=${parcelaId}`).
- [ ] (ROADMAP #2) `ParcelasScreen` muestra cada parcela con `nombre`, `codigo`, `gruposCount`, `treesCount`, `OrangeDot` cuando `pendingSyncBelow || pendingSync`. **No** muestra `descripcion` (D-17-05).
- [ ] (ROADMAP #3) Header tiene icono `+` a la derecha que abre `ParcelaFormModal` en modo crear (D-17-08).
- [ ] (ROADMAP #3) Long-press sobre `ParcelaRow` abre `ParcelaFormModal` en modo editar (D-17-06).
- [ ] (ROADMAP #4) Empty state con CTA grande "Crear primera parcela" cuando `parcelas.length === 0` (D-17-07).
- [ ] `ParcelaFormModal` es full-screen en create y edit (D-17-01), incluye contador `1234 / 10000` con color warning ≥9000 (D-17-02), valida unicidad on-submit (D-17-03), bloquea delete con modal de error si la parcela tiene grupos (D-17-04).
- [ ] `npx tsc --noEmit` queda en 0 errores.
- [ ] `npm test -- ParcelaFormModal` y los tests touched no rompen.

## Risks & Mitigations

1. **`useParcelas` necesita `usePlantationDetail` o query separada para obtener `lugar`** — `useParcelas` solo devuelve parcelas, no metadata de plantación. Mitigación: en Task 1.4 usar `usePlantationDetail(plantacionId)` para leer `plantationRows?.[0]?.lugar` y pasarlo al título; función pequeña ≤20 líneas.
2. **Modal full-screen vs route stack screen** — D-17-01 dice "full-screen modal". Mitigación: implementar como `Modal` con `presentationStyle="fullScreen"` (RN), no como ruta separada. Más simple, mismo UX. Si emerge fricción durante 17-01, podemos pivotar a screen route en una refacción menor.
3. **Doble route wrapper (admin + tecnico)** — duplicación. Mitigación: ambos wrappers son una sola línea de re-export del mismo `ParcelasScreen`. Sin lógica duplicada (cumple CLAUDE.md §8). Es el patrón ya establecido en `nuevo-subgrupo.tsx`.
4. **`PlantacionesScreen` redirige a `parcelas` pero `[id]` queda apuntable** — riesgo de quedar accesible por deep link. Mitigación: aceptado en este plan; 17-03 refactoriza `[id]` para recibir `parcelaId` y filtrar (no se elimina la ruta).
5. **`descripcion` 10k chars consume memoria en RN TextInput** — TextInput multiline con strings muy largos puede ser lento. Mitigación: usar `maxLength={10000}` como hard cap, no implementar autocomplete/syntax-highlight, dejarlo como text plain.
