## Risks & Mitigations

1. **`PlantationDetailScreen` es complejo (≈190 LOC) y este plan lo refactoriza profundamente** — riesgo de romper subgrupo edit modal, N/N resolution navigation, deletes. Mitigación: tasks 3.2 + 3.3 separadas (hook vs screen), `npx tsc --noEmit` + run app entre cada commit, memory `feedback_refactor_audit.md` (diff old vs new).
2. **El rename "subgrupo"→"grupo" puede colisionar accidentalmente** con strings que dicen "grupo" ya (no aplican rename) — riesgo bajo (case-sensitive helper). Mitigación: usar `sed -i '' 's/Subgrupo/Grupo/g; s/Subgrupos/Grupos/g; s/subgrupo/grupo/g; s/subgrupos/grupos/g'` por archivo, NO global; revisar cada diff antes de commit. Alternativa más segura: edits manuales con `Edit` tool en cada archivo (preferida — diff es chico y auditable). D-17-20 confirma "rename literal directo funciona".
3. **`git mv nuevo-subgrupo.tsx nuevo-grupo.tsx` puede generar conflict en CI** si hay PRs paralelos modificando ese archivo — improbable porque trabajamos en `gsd/v1.1-phase-15-context`. Mitigación: hacer el rename como último task antes del checkpoint, en un commit aislado.
4. **`validateGroupUniqueness` per-parcela rompe edits de grupos existentes** que estaban migrados con códigos colisionables a nivel plantación pero únicos a nivel parcela. Mitigación: la consolidación de Phase 15-03 ya hizo el SubID recompute respetando esto; los tests existentes deben pasar. Si rompe, fallback al check per-plantacion con warning log (ya planeado).
5. **El visual checkpoint depende del usuario con device físico** — si no hay device disponible, el checkpoint queda colgado. Mitigación: documentar en el resume signal que es OK reportar issues sin completar el flow 100% (en cuyo caso, queda gap-closure para 17-04).
