## Goal

Cerrar EXPO-PARC-01..02: ampliar el export CSV/Excel para incluir las columnas `Plantación` (`plantation.lugar`) y `Parcela` (`parcela.nombre`) en el orden exacto definido por ROADMAP SC#5: **`ID Global, ID Parcial, Zona, Plantación, Parcela, Grupo, SubID, Periodo, Especie`**. Extender `exportQueries.getExportRows` con un `LEFT JOIN` a `parcelas` para traer `parcela.nombre` por tree (LEFT, no INNER, porque pueden existir grupos legacy sin `parcelaId` — D-18-10 retorna `""`). Renombrar el header `SubGrupo` → `Grupo` (consistencia post-Phase 17). Cerrar el milestone v1.1 con un visual checkpoint manual en device.

## Success Criteria

Mapea a ROADMAP Phase 18 success criteria:

- [ ] **SC#5** El CSV exportado contiene exactamente las 9 columnas en el orden: `ID Global, ID Parcial, Zona, Plantación, Parcela, Grupo, SubID, Periodo, Especie`. El Excel exportado contiene los mismos 9 headers en el mismo orden.
- [ ] **SC#5** Columna `Plantación` = `plantation.lugar` (D-18-09). Columna `Parcela` = `parcela.nombre` (NO `codigo`, EXPO-PARC-02). Si un tree pertenece a un grupo sin parcela (legacy), la celda Parcela es `""` string vacío (D-18-10).
- [ ] **SC#6** Tests unitarios verifican: el header CSV string exacto, las claves del Excel sheetData, valores de parcelaNombre presentes en filas con parcela vinculada, valores `""` en filas sin parcela.
- [ ] **Checkpoint final** (cubre SC#2 del Plan 18-01 también): en device real, crear una plantación nueva con flag ON, ver "Parcela 1" auto-creada, registrar trees, exportar CSV, verificar visualmente que las 9 columnas están presentes y los valores son correctos.

## Task Breakdown

### Task 2.1: Extender `exportQueries.getExportRows` con JOIN a parcelas + plantacionLugar separado

- **Files:** modify `mobile/src/queries/exportQueries.ts`
- **What:**
  - Importar `parcelas` desde `../database/schema`, e importar `leftJoin` / usar `eq` con `isNull`-safe (Drizzle: `.leftJoin(parcelas, eq(groups.parcelaId, parcelas.id))`).
  - Cambiar el JOIN entre `groups` y `parcelas` a `leftJoin` (un grupo legacy puede tener `parcelaId=null`).
  - Extender la interfaz `ExportRow`:
    ```ts
    export interface ExportRow {
      globalId: number | null;
      idParcial: number | null;
      lugar: string;            // = plantacion.lugar — kept for backwards compat (Zona column legacy)
      plantacionLugar: string;  // NEW — column "Plantación"
      parcelaNombre: string;    // NEW — column "Parcela", "" si null (D-18-10)
      grupoNombre: string;
      subId: string;
      periodo: string;
      especieNombre: string;
    }
    ```
    Comentario: actualmente "Zona" y "Plantación" muestran el mismo dato (`plantation.lugar`); mantener ambos por explícita decisión D-18-09 hasta que se defina una "Zona" distinta. Si se decide colapsar, es 1-line refactor futuro.
  - SELECT debe agregar `plantacionLugar: plantations.lugar` (alias) y `parcelaNombre: sql<string>\`COALESCE(${parcelas.nombre}, '')\`` (o equivalente Drizzle: `parcelaNombre: parcelas.nombre`, manejar null en el `.map(...)` consumidor en ExportService).
  - Preferir manejo en el consumidor (más simple): retornar `parcelaNombre: string | null` desde la query, normalizar `?? ''` en ExportService (D-18-10).
  - Mantener `lugar` apuntando a `plantations.lugar` (sin cambios) por compatibilidad con la columna "Zona".
- **Why:** EXPO-PARC-01 + EXPO-PARC-02, D-18-09, D-18-10.
- **Verification:** `cd mobile && npx tsc --noEmit` limpio; Task 2.3 cubre la query con tests.

## Risks & Mitigations

1. **LEFT JOIN a parcelas degrada performance del export en plantaciones con miles de trees.**
   Mitigación: 7.579 trees totales en producción (post-Phase 15) — performance OK; índice en `parcelas.id` ya existe (PK).
2. **`parcelaNombre: null` se serializa como `null` (texto literal) en CSV/Excel si no se normaliza.**
   Mitigación: normalizar `?? ''` explícitamente en ExportService (D-18-10). Test 2 de exportQueries verifica el valor crudo; tests de ExportService verifican la normalización.
3. **Header `SubGrupo` puede haber sobrevivido en otros sitios además de ExportService.**
   Mitigación: Task 2.4 incluye grep gate global. Phase 17-03 ya debió haberlos renombrado; cualquier residuo se fixea en Task 2.4.
4. **El checkpoint requiere un device real / emulator funcional + Supabase live.**
   Mitigación: ya es práctica establecida del proyecto (memory `project_android_only.md`); fallback es usar Android emulator con la URL de Supabase configurada en `eas.json`.
5. **Si Phase 17 dejó un `Zona`/`Plantación` redundante** (ambas muestran `lugar`): el usuario puede pedir colapsar. Decisión D-18-09 dice **mantener ambas**.
   Mitigación: documentado en JSDoc de `ExportRow`; refactor futuro 1-line si el equipo lo confirma post-prueba en campo.
